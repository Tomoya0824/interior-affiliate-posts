# Room Totonoe 投稿文の書き方

毎朝の定期実行でClaudeが読むルールです。1日3本（朝の問いかけ・昼のコツ・夜の商品）の投稿文を書きます。

## アカウントの立ち位置

- 「おしゃれな家具・照明・インテリア雑貨で、部屋を垢抜けさせる」アカウント（2026-11-09 に方向転換。それまでは収納・寝具・キッチン用品中心）
- 読み手は、ワンルームや2LDKくらいの部屋で「おしゃれな部屋にしたいのに、なんだか垢抜けない」「何を足せばいいかわからない」と悩んでいる人
- 目指すのは「広告っぽい商品紹介」ではなく「部屋づくりに詳しい人の、気の利いたおすすめ」。投稿を読んだあと、自分の部屋で今日すぐ1つ試せること
- 口調は丁寧すぎない「です・ます」。友人に教えるくらいの温度感。絵文字は使わないか、1つまで

## 今の方針（2026-11-13 改訂）

開始1週間で「伸びない・売れない」状態だったため、次のように切り替えた。

1. **まずフォロワーと反応を増やす段階**。Threadsは「返信」がいちばん効く。どの投稿も、最後は返信したくなる問いかけで終える
2. **1行目で指を止める**。タイムラインでは1行目しか読まれない。1行目だけで「自分のことだ」「続きが気になる」と思わせる（下の「1行目の型」）
3. **商品投稿は「3選」が基本**。候補3つを画像3枚のカルーセルにして比べてもらう。1つを推すより反応（「②が好き」）が付きやすく、好みの合う商品が見つかりやすい
4. **リンクは本文に入れない**。Apps Scriptが本文の下に「楽天市場のリンクはリプ欄に置いています」と付け、自分の投稿へのリプ欄にリンクを置く（楽天のガイドラインで許可されている置き方）
5. **数字を見て決める**。毎晩 `queue/insights/` に閲覧数・返信数・リンクのクリック数が保存される。毎朝それを読み、伸びた型を増やし、伸びない型を減らす（下の「数字の見方」）

## 1行目の型（どの投稿にも使う）

1行目は30文字以内で、改行して2行目に続ける。次の型を日替わりで使い、`hook` に型の名前を書く（数字で比べるため）。

| hook | 型 | 例 |
| --- | --- | --- |
| number | 数字・条件で絞る | 「天井の明かりだけの部屋に足したい、照明3つ」 |
| aruaru | あるある・小さな失敗 | 「おしゃれな家具を買ったのに、部屋が垢抜けない理由」 |
| scene | 人物の一場面 | 「仕事を終えて照明を消すと、部屋が急に寒々しく見える夜」 |
| question | 二択・問いかけ | 「部屋の明かり、白い光とオレンジの光、どっち派ですか？」 |
| contrast | 意外な対比 | 「家具を買い足すより、先に照明を1つ足したほうが早い」 |

- 1行目に商品名・ブランド名・価格を置かない
- 「必見」「保存必須」「知らないと損」のような煽りは使わない
- 直近7日に同じ `hook` が3回以上あれば別の型にする（数字で特定の型が明らかに強い場合は、その型を週4回まで使ってよい）

## いちばん大事なこと：ひとりの暮らしを思い浮かべて書く

投稿は「みんな」に向けて書かない。毎回、下の「暮らしの人物」から1人を選び、その人のある日のある瞬間を具体的に思い浮かべてから書く。読んだ人が「これ、私のことだ」と感じる一場面を切り取ることで、共感が生まれ、商品が「自分の暮らしに必要なもの」に見えてくる。

### 共感を生むためのコツ

- 気持ちは大げさにしない。「ちょっと気になる」「毎回少し面倒」くらいの小さな本音が一番共感される
- 説明するより、場面を見せる（「寒い」より「指先が冷えてキーボードを打つ手が止まる」）
- 人物の年齢や属性を本文に書き並べない。場面から自然に伝わるようにする
- 文の最後は言い切りすぎず、余韻を残す

### 人物を使うときの守ること

- 人物はあくまで「場面を想像するための設定」。実在の人の話や購入者の声として書かない
  - NG：「30代の〇〇さんは、これを買ってから毎晩ぐっすり」「愛用者の声：…」
  - OK：「〜な夜。」「〜していませんか。」のように、読み手が自分を重ねられる書き方
- 紹介者（このアカウント）が使ったように書かない（下の「絶対に書かないこと」を参照）

## 絶対に書かないこと

- **使った体験の捏造**：「使ってみたら」「我が家では」「買ってよかった」など、実際に使ったように見える書き方はしない（紹介者の立場で書く）
- **体への効果**：「肩こり」「腰痛」「快眠」「安眠」「疲れがとれる」「健康に」「痩せる」など、体や健康に効くと受け取れる表現（薬機法）。寝具は素材・厚み・手入れ・サイズで紹介する
- **言い切りの誇張**：「最強」「絶対」「一番」「間違いない」「神アイテム」
- **データにない情報**：レビューの中身、売上順位、在庫・セール・クーポン情報、送料の有無
- **価格**：価格は変わるので本文には書かない（「1万円以下」のような価格帯も書かない）。リプ欄にApps Scriptが投稿時点の価格を付ける
- 本文に「#PR」「【PR】」、リンク、ハッシュタグは書かない（自動で付く）
- リンクのクリックや購入を頼む言葉（「リンクから買ってね」「チェックしてみて」「今すぐ」）。リプ欄の案内はApps Scriptが付けるので、本文では触れない

## 夜の商品投稿（queue/posts/YYYY-MM-DD.json）

### 形式

- **pick（3選）**：基本。候補3つ（ときに2つ）を比べる。画像は各商品の1枚目がカルーセルになる
- **single（1品）**：候補の中に明らかに1つだけ良い商品があるとき、または数字で single のほうが強いとわかったとき。画像はその商品の写真（最大3枚）

迷ったら pick。週に1〜2回は single にして、数字で比べられるようにする。

### 本文の組み立て（pick）

本文は150〜320文字。Apps Scriptが先頭に【PR】、末尾に「楽天市場のリンクはリプ欄に置いています」を足すので、本文には書かない。

1. **1行目**：「1行目の型」から1つ（例：「ソファの横に置くだけで、夜の部屋が変わるもの3つ」）
2. **共感の一場面（1〜2文）**：暮らしの人物の「ある瞬間」。小さな本音で
3. **①②③**：1商品につき1〜2行。商品説明にある事実（素材・色・形・サイズ）1〜2つと、「どこに・どう置くか」を1つ。①②③の順は画像の順（`items` の順）と同じにする
   - 例：「①ガラスのペンダントライト　泡とひび模様のシェード。ダイニングテーブルの上に1灯だけ低めに」
   - 3つは「タイプ違い」になるように書き分ける（例：かわいい系／シンプル系／存在感のある系、小さめ／大きめ）
4. **問いかけ（1文）**：「どれが好きですか？番号で教えてください」「①〜③、自分の部屋ならどこに置きますか？」のように、番号で一言返せる問い

### 本文の組み立て（single）

本文は100〜200文字。1行目の型 → 共感の一場面 → その場面がどう変わるか（事実と置き方） → 問いかけ。

### 商品の選び方

候補が3つあるので、pick なら3つとも使う（明らかに使えない1つがあれば2つで pick）。single なら次の順で1つ選ぶ。

1. 季節外れの商品（冬に冷感グッズなど）は選ばない
2. 見た目で選ばれる商品（照明・雑貨・家具・ミラー）を優先する
3. 説明文から具体的な特徴（素材・色・形・サイズ）を3つ以上読み取れる商品を優先する
4. 直近7日の投稿と同じ種類は避ける
5. 数字（`queue/insights/` のリンクのクリック）でクリックされた種類・価格帯に近いものを優先する

候補が使えない内容（説明が乏しい・季節外れ・同じ商品が3つ並ぶなど）でも、事実だけで短めに書く。

### 出力の形式

```json
{
  "date": "2026-11-14",
  "format": "pick",
  "hook": "number",
  "persona": "solo-remote",
  "scene": "仕事を終えて天井の照明を消すと、部屋が急に寒々しく見える",
  "body": "本文（ハッシュタグ・リンク・価格・【PR】は書かない）",
  "topic": "照明",
  "items": [
    { "code": "候補の code", "label": "ガラスのペンダントライト" },
    { "code": "候補の code", "label": "花の形のペンダントライト" },
    { "code": "候補の code", "label": "天然木の4灯ライト" }
  ]
}
```

- `items` の順に、カルーセルの画像とリプ欄のリンク（①②③）が並ぶ。single なら `items` は1つ
- `label` は本文の①②③と同じ呼び名（20文字以内。ブランド名・誇張は入れない）。リプ欄に「【PR】①ガラスのペンダントライト／★4.75（レビュー831件）・7,287円〜／楽天市場で見る ▶ リンク」の形で出る
- `topic` はトピックタグ。1つだけ、`#` なしで（下の「トピック」）

## 昼のお役立ち投稿（queue/tips/YYYY-MM-DD.json・リンクなし）

商品紹介だけが続くと「宣伝アカウント」に見え、楽天のスパム規定にも触れやすくなる。毎日1本、リンクも商品名もない「部屋づくりのコツ」を投稿する。これがフォローされる理由になり、夜の商品投稿が届く人を増やす。

- **本文は140文字以内**（目安は100〜140文字）
- テーマは「部屋を垢抜けさせる」こと：家具の配置・照明・色の合わせ方・飾り方・見せる収納・部屋が広く見える工夫・季節のしつらえ から1つ
- 「暮らしの人物」から1人を選び（夜の商品投稿とは別の人物にする）、1行目は「1行目の型」を使う
- 組み立ては **1行目（型）→ 具体策（手順や数字：cm、色の数、個数）→ 問いかけ**
- 誰でも知っている一般論だけで終わらせない
- 商品名・ブランド名・リンク・#PR・価格・ハッシュタグは書かない
- 直近7日の queue/tips/ と同じテーマ・同じ切り口を続けない
- 確認できない事実は断定しない。素材の効果・数値の根拠・「〇〇と言われています」のような豆知識は書かない。迷ったら、配置や色の工夫など、事実確認の要らない「やり方」にする
- 2026-12-09 までストックがある（改訂前に書いたもの。1行目の型は使っていないが、そのまま使う）。その日のファイルが既にあれば新しく書かない

```json
{
  "date": "2026-12-10",
  "theme": "玄関の片付け",
  "hook": "aruaru",
  "persona": "dual-kids",
  "body": "本文（140文字以内）",
  "topic": "部屋づくり"
}
```

## 朝の問いかけ（queue/morning/YYYY-MM-DD.json・リンクなし・9時台）

返信を集めるための短い投稿。会話が生まれると、昼と夜の投稿も届きやすくなる。

- **本文は30〜100文字**。商品名・リンク・ハッシュタグ・価格は書かない
- 一言で答えられる問いにする：二択（「白い光とオレンジの光、どっち派？」）、番号・一単語（「部屋でいちばん好きな場所はどこですか？」）、小さなあるある（「照明のスイッチを入れた瞬間、部屋が思ったより暗いことありませんか？」）
- その日の夜の商品と、テーマを軽くつなげてもよい（夜が照明なら、朝は「部屋の明かり」の問い）。ただし商品の話はしない
- 直近7日の queue/morning/ と同じ問いを続けない

```json
{
  "date": "2026-11-14",
  "theme": "部屋の明かりの色",
  "hook": "question",
  "persona": "solo-remote",
  "body": "本文（30〜100文字）",
  "topic": "インテリア"
}
```

## トピック（topic）

Threadsは1投稿に1つだけトピックタグが付く。本文にはハッシュタグを書かず、`topic` に1つだけ `#` なしで書く（Apps Scriptが付ける）。商品と関係あるものだけ。

候補：インテリア / 部屋づくり / 照明 / おしゃれ家具 / インテリア雑貨 / 一人暮らし / 北欧インテリア / 暮らしを整える / 冬支度 / クリスマス

## 数字の見方（毎朝、書く前に）

`queue/insights/` の最新のファイル（前夜23時台に保存）を読む。無ければこの手順は飛ばす。

- `posts[]`：直近7日の投稿ごとの `views`（閲覧）・`replies`（返信）・`likes`・`reposts`・`shares`。`kind`（morning / tips / product）、`format`、`hook` で比べる
- `account.linkClicks`：リンクごとのクリック数。どの商品（種類・価格帯）がクリックされたかを見る
- `account.followers`：フォロワー数

判断のしかた（データが少ないうちは決めつけない。3投稿以上そろってから）：

1. 同じ `kind` の中で、`views` と `replies` が平均の1.5倍以上の投稿の `hook`・テーマ・人物を、次の投稿で優先する
2. `views` が平均の半分以下の型は、その週はもう使わない
3. クリックされた商品と同じ種類・価格帯を、商品選びで優先する
4. pick と single は、`views` と商品投稿のクリック数で比べる。1週間で差がはっきりすれば、強いほうを週5回にする
5. 気づいたことは `docs/insights-log.md` に日付つきで1〜3行追記する（「hook=number の昼投稿が views 2倍」など）。翌日以降はそのログも読む

## 書いたあとの見直し（毎回）

1. **文字数**：朝 30〜100、昼 140以内、夜 pick 150〜320 ／ single 100〜200
2. **1行目**：30文字以内で、型に沿っているか。商品名・価格から始めていないか
3. **重複**：直近の投稿（queue/morning/・queue/tips/・queue/posts/、ストック分も含む）と、テーマ・1行目・具体策が重なっていないか
4. **抽象的な表現**：「おしゃれに」「すっきり」「いい感じに」だけで終わっていないか
5. **事実確認**：商品の事実は name・catchcopy・caption・sizes にあるものだけか。確認できない事実を断定していないか
6. **禁止表現**：「絶対に書かないこと」と、本文にハッシュタグ・リンク・【PR】・価格が無いか（Apps Scriptは、禁止語やハッシュタグを含む本文を投稿しない）
